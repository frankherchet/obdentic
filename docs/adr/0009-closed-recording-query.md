# 0009. Closed recording queries at the shared replay boundary

Date: 2026-11-19  
Status: proposed

## Context

[#365](https://github.com/frankherchet/obdentic/issues/365) asks whether the approved closed jq text subset can satisfy [REQ-049](../requirements.yaml) on Android at the shared [#306](https://github.com/frankherchet/obdentic/issues/306) replay boundary. One focused design session; synthetic inputs only. The owner approved the exact syntax and budgets in [#358](https://github.com/frankherchet/obdentic/issues/358#issuecomment-6994093640). This is not build approval. No recording query implementation, Android prototype, hardware, model, account or private recording was used here.

## Options considered

1. The approved candidate is a **closed textual jq-style subset** over the shared replay interpretation. Its implementation and dependencies are not selected or approved by this ADR. It must accept every form in REQ-049.19, not merely a typed API or a narrower set of convenient examples.
2. Embedded/full jq was mentioned in the original spike question but the later approved input expressly excludes it as the evaluated alternative. It is not an approved fallback. Full jq's broader facilities cannot be assumed safe or necessary.

Neither option authorizes a second vehicle decoder, a second independent replay interpretation, or a mandatory index. The input boundary is one user-selected logical recording via an opaque handle, not paths supplied in expressions.

## Measurements

These are source observations and paper inputs, not executed tests or measured performance.

- **M1 — accepted text and limits.** REQ-049.4, .11–.17 and .19–.24 specify field access; literal `== != < <= > >=`; `and`; `map(select(...))`; object projection; `length`; `map(.value) | add / length`; start-inclusive/end-exclusive windows; event-order pages; revision/query-bound cursors; mean over all matches; and no mean on an empty selection. Limits per call are 100,000 input lines, 32 MiB input, 200,000 operator evaluations, 1 second and 8 MiB intermediate memory. Page limits are 100 hits and 64 KiB encoded output; an oversized single row is a typed output limit. Like-for-like release APK increase must not exceed 8 MiB. The #365 approved inputs require independently isolating limits and documenting rights and costs.
- **M2 — jq language.** The [official jq 1.8 manual](https://jqlang.org/manual/) describes filters operating on input, pipe composition, `map(f)` as `[.[] | f]`, and `select(f)` as retaining its input when true. Both operands of `/` receive the same input: `add / length` averages an array; `add` on an empty array returns `null`, and division by zero raises an error. Thus `map(.value) | add / length` averages the mapped values, not a page's original event array. jq can also read modules and files via other facilities; none is authorized by REQ-049.19. The approved contract is jq-*style*, not a claim that every jq behavior or facility is supported.
- **M3 — replay and source evidence.** #306 describes an as-yet shared whole-mobile-recording replay returning a snapshot; its owner decision requires aborting on Knowledge-pin mismatch. Current [`src/mobile/report.rs`](../../src/mobile/report.rs) has an offline `MobileCore` replay walker, per-file 64 MiB and 200,000-line limits and a `report_set` path for coverage; this is not the completed #306 shared query seam. [`src/capture_replay.rs`](../../src/capture_replay.rs) concerns a separate capture format, re-decodes raw responses with the current semantic decoder and preserves original interpretation separately. Its [`capture_format/jsonl.rs`](../../src/capture_format/jsonl.rs) reader reads an entire file and collects events, so it is not evidence of a bounded mobile-recording query API. [#339](https://github.com/frankherchet/obdentic/issues/339) specifies ordered rotated coverage parts and partial gaps; coverage-specific markers are not proven to identify every recording's rotation chain. Current sources do not establish a revision-bound, per-original-event query interface at #306.
- **M4 — Android target.** [`android/app/build.gradle`](../../android/app/build.gradle) sets ARM64 (`arm64-v8a`), min API 26, compile/target API 36, Java 17 and `minifyEnabled false` for release; release requires signing configuration. [`docs/android.md`](../android.md) identifies Rust 1.98.0, Android SDK platform 36, build tools 35.0.0, NDK 27.2.12479018 and `aarch64-linux-android`. No baseline or candidate APK was built or sized; neither package-size delta nor execution cost is observed.
- **M5 — rights.** No evaluator dependency or version has been selected, so its complete redistribution rights and transitive notices cannot yet be established. The [jq upstream COPYING](https://raw.githubusercontent.com/jqlang/jq/master/COPYING) grants jq redistribution under stated notice conditions and lists other included-code notices and a separate documentation license; this alone does not establish the rights, build configuration, transitive dependencies or packaging of any proposed Android evaluator. No jq dependency is presumed.

### Paper dry run of the fixed criteria

This is a test design, not a result. Conceptual fields below illustrate the query schema to be documented by #306/#358; they do not assert the present mobile envelope has these names. On paper, the expected aggregate for valid numeric matches is count 2 and `(800 + 1200) / 2 = 1000`.

| Area and input/precondition | Observation needed; confirm / refute / inconclusive |
|---|---|
| Text and filtering | For an array of replay-interpreted events, a documented form such as `map(select(.time >= 10 and .time < 20 and .signal == "rpm"))` selects the approved half-open window; separate supported examples exercise all six comparisons, field access, object field projection and `length`. Confirm only when the actual documented schema and parser execute all approved forms; refute on rejection or wrong result; schema/parser absent is inconclusive. This is not permission to replace the approved text with a structured filter. |
| Rotation and evidence | Part A has synthetic RPM 800 at 10, part B 1200 at 19, and a sample at 20 is excluded; keep exact original part and line/event identity through replay interpretation and projection. Confirm count 2, mean 1000 and both references resolve to the original events; distinguish interpreted values from original evidence. Also separately select DTC and UDS without unrelated samples. Missing part/corrupt record is identified and partial or not evaluable; pin mismatch and unknown schema stop. A snapshot alone cannot demonstrate event provenance. Refute wrong or fabricated reference/result; unavailable shared seam is inconclusive. |
| Paging and aggregate | On more than 100 matching ordered events across two parts, concatenate all pages and compare against original order, no duplicate/skip; repeat for identical boundaries. Use sizes straddling 64 KiB as well as 100 hits, and a single row larger than 64 KiB: typed output limit, no skipped row or non-advancing cursor. Cursors from another query, recording or revision are refused. Compare aggregate against all matching events rather than one page. Refute a mismatch; absent implementation is inconclusive. |
| Empty mean | An empty selection yields count 0 and **no mean** at the tool boundary. Raw jq's empty `add / length` is not a numeric zero and errors; an implementation must handle the approved empty outcome without claiming raw jq returns it. Confirm only from the actual tool response; absent evaluator is inconclusive. This wrapper-level outcome does not by itself contradict a jq-style subset. |
| Closed language and scope | Submit e.g. `import "x" as x; .`, `..`, an unsupported operator, and a path/unselected handle or agent-audit target. Confirm typed refusal before execution/access, and no module, file or process access; refute any escape or rejected required syntax. Invalid syntax must not be laundered into a different supported query. Absence of implementation or an observable access boundary is inconclusive. |
| Lines | With independently controlled clock, memory, encoded bytes and work, fixture A completes at exactly 100,000 input lines; fixture B requires one more and stops before processing it, typed line limit and partial prefix if returned. Refute wrong behavior; inability to keep other limits below their caps makes this fixture inconclusive, not a pass. |
| Input bytes | Controlled fixtures consume exactly 32 MiB and require one additional input byte respectively, with other caps below their boundaries. Confirm completion at the cap and stop before exceeding it, typed byte limit and partial prefix. Account consistently for actual input bytes; fixture feasibility and accounting remain to be demonstrated. |
| Operator evaluations | Define and instrument the documented evaluation unit; complete exactly 200,000, and separately require evaluation 200,001 without performing it. Keep every other cap below its boundary. Confirm typed work limit and partial prefix; an undefined counter or competing limit is inconclusive. |
| Time | With an injected controlled monotonic clock, complete at exactly 1 second and separately attempt work beyond it; verify typed time limit, no work past the limit and partial prefix. Other caps remain below their boundaries. This is a deterministic boundary test, not an Android performance measurement. |
| Intermediate memory | Instrument all memory included in the agreed intermediate-memory accounting, including replay and evaluator allocations within the call; construct exactly 8 MiB and a next operation requiring one byte more. Confirm the former completes and the latter allocation is not performed, typed memory limit and partial prefix, with other caps below their boundaries. Unspecified accounting, allocator overhead or an unavailable seam makes the result inconclusive. |
| Cancellation | Cancel during a synthetic scan after an observable prefix; confirm termination, cancellation outcome and partial prefix, never a complete aggregate. Also cancel before any result. Lack of an observable cancellation boundary is inconclusive. |
| Android / rights | Compare baseline and candidate signed release APKs with identical source except the candidate, toolchain, ABI, versions, build settings and signing method. Record sizes and delta, and runtime evidence for this same supported target; inventory exact shipped direct/transitive dependencies, versions, license texts and required notices. Confirm only if delta ≤ 8 MiB, applicable terms permit distribution with obligations met, and the other criteria have actual bounded evidence. A measured exceedance or conflicting rights refutes; no comparable build, runtime evidence or complete rights inventory is inconclusive. |

No paper input requires a forbidden fallback or changes an approved numerical value. Dry run: **no demonstrated logical conflict** between approved criteria; feasibility remains unproved. In particular, the shared replay constraint requires a future event/provenance seam, not permission to invent a parallel decoder. A snapshot-only implementation cannot establish the required references, but #306 is open and its direction does not preclude extending the shared seam.

## Criteria verdict

- **Confirm — inconclusive (M1–M5):** no candidate execution, shared replay event seam, isolated boundary/cancellation observations, rights inventory, runtime measurement or release APK comparison exists. Paper expectations are not observations of a working evaluator.
- **Refute — inconclusive (M1–M5):** no disallowed escape, proven unbounded approved query, exceeded limit/APK budget, or incompatible dependency license was observed. A missing implementation or the current snapshot direction is not evidence of impossibility.
- **Inconclusive condition — met (M3–M5):** shared #306 event seam, candidate dependency rights, and Android packaging/runtime evidence remain unverified. The approved syntax and numbers themselves are available (M1), not open preferences.

## Uncertainty

No criterion has been amended. The future documented event schema, precise expression grammar around the required forms, numeric/type behavior, encoded page accounting, work-unit definition, memory accounting and cursor/revision representation need specification consistent with all accepted criteria; none may narrow them. In particular, clarify how the tool maps an empty aggregate to no mean without presenting jq's raw division error as a result. Independent fixtures must demonstrate that the other four budgets do not bind first; time and allocator accounting must include the shared replay work, not merely a query wrapper. The approved one-second stop is a testable controlled-time condition, not a proven real-device latency guarantee.

#306 currently describes all-at-once replay; whether its eventual shared interface can expose ordered original events, check cancellation and account resources while preserving provenance is an open implementation question, not a measured impossibility. The whole-file capture reader and current mobile report are distinct paths and must not be conflated. Likewise, #339 coverage linkage is not proof that arbitrary old or non-coverage recordings have complete rotation metadata. Resolve missing evidence as partial or not evaluable, never infer complete continuity. No license conclusion can substitute for reviewing the exact eventual dependency closure and notice obligations.

## Decision

**No feasibility or engine decision is made.** Retain the owner-approved closed textual subset, shared replay interpretation and all exact budgets as the constraints to investigate. Do not approve a separate decoder, an embedded jq fallback, a dependency, or an Android packaging claim. Acceptance of an ADR is a separate human decision; an inconclusive criterion cannot be accepted as proven.

## Consequences

#358 remains dependent on #306 and on evidence for the shared per-event/provenance and bounded-execution boundary. Before implementation readiness is claimed, obtain the missing synthetic boundary and cancellation evidence, supported-Android release APK comparison, runtime evidence and complete shipped-dependency rights inventory. Any actual conflict found later must be reported with a proposed amendment for human approval; do not silently change the accepted text or numbers. This session did not run tests, builds or hardware checks.
